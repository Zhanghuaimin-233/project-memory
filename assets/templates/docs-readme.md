## 维护约定

<!-- 项目已有这些规则时只链接，不重复抄写。 -->

- 优先修正已有说明。同一事实只维护一个当前解释；代码、测试或已有材料足够时，不新增文档。
- Plan 表达当前有效方案：直接改写失效步骤，State 不长期累积计划补丁。调整方法不能静默减少目标或验收。
- 确需替代 Plan 时，旧稿保留正文并标记 `superseded`，新旧互链；新版承接完整剩余范围、约束与验收，本入口只指向当前版本。
- State 只在存在值得保存的接续信息时使用，沿用同一份当前快照；已解决且不影响下一步的内容退出快照。不要删掉仍有影响的必要约束、危险中间状态或尚未保存的唯一证据。
- 有价值的独立后续工作使用已有 Issue/待办；当前任务必做项不能移过去就算完成。难以重建的证据和可复用经验按价值保存，没有就不写。
- 文档与代码或运行结果冲突时先调查，不自动假定任一方正确。完成任务后撤下活跃入口，历史按实际需要保留，不为归档而强制移动或删除。
