## 项目文档路由

- 新建长期文档前先读取 `<文档入口>`，按其中的类型、命名和生命周期规则落位。
- 优先更新已有权威文档，不为同一主题创建平行的“新版”“最终版”。
- 任务预期行为、初步接口和验收条件优先写入 Plan；实施中确认、推翻或待验证的结论写入唯一 State。
- State 只记录任务现实和相对 Plan 的偏差，不与 Plan 并行维护第二份完整规格。
- Spec 不是默认产物。只有任务完成后仍被跨任务持续依赖，且独立文档比代码、Schema 和测试更有解释价值时，才创建或更新 Markdown Spec。
- 修改已有 Spec 时，完成态结算前由 Plan 和 State 描述拟议变化，现有 Spec 仍代表当前正式行为。
- AGENTS 只保存 Agent 工作方式、文档路由和少量所有任务都必须知道的护栏，不复制完整产品或接口合同。
- 当前事实、Spec、Plan、State、Report、Knowledge 和 Archive 不能互相冒充。
- 未完成任务跨会话时维护同一份 `STATE.md`，不得按会话创建新交接文件。
- 文档与代码、测试或运行结果冲突时先调查，不直接假定任何一方正确。
- 任务完成后的正式同步、知识提炼和归档使用项目声明的收尾流程。

### 入口

- `<当前状态文档>`：项目当前目标、能力、结构和限制。
- `<文档入口>`：完整文档地图与新文档创建规则。
- `<活跃任务目录>`：未完成长期任务的状态快照。
- `<计划目录>`：实施意图，不代表当前实现。
- `<报告目录>`：调查与验证证据，不代表正式规格。
- `<知识入口>`：非直观且可复用的项目经验；根据任务按主题读取。
- `<归档目录>`：历史资料，默认不读取。

只保留项目真实存在的入口，删除模板中的空项。
