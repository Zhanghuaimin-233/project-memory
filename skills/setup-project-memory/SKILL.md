# 建立或修复项目资料

让人和 Agent 以较小成本理解项目并正确继续工作。资料应准确、易查、易理解、易更新；形式和数量由实际用途决定，不以文件少、目录齐全或图表丰富作为完成标准。

## 找到真正妨碍工作的地方

确认用户要理解项目、建立新项目资料，还是恢复某项任务。新会话不代表新项目，旧项目也不必重新 setup；用户要继续明确任务时按任务现场接续即可。接手目的有实质歧义时先澄清，不从某份 State 猜测用户要做什么。

确认项目根、适用规则、相关 Git 改动和已有入口。围绕当前目的查明项目目标、相关结构、重要约束、决策理由和实际状态；按线索读取资料与代码，不默认逐份读取所有历史。新项目只保存已经明确的认识，未知架构和需求保留为未知。

辨别妨碍接手的问题：使用方法缺失、关系难以理解、决定原因失落、当前工作找不到，还是多份材料互相冲突。现有资料已足够时可以零改动结束；用户只要求审查时，只提供有依据的发现和建议。

明确要求全仓项目资料审查时，盘点相关入口与声明，沿来源核对冲突、失效引用和覆盖缺口，说明未覆盖范围。代码与运行态用于核对资料，不因此扩展到通用代码审计、部署或工作区清场。

文档、代码、测试和运行证据冲突时，先调查是文档过期还是实现偏离约定。日期较新、代码已经存在或计划打了勾，都不能单独证明正确，更不能据此改小用户目标。

## 只补实际缺口

- 先选最能回答当前问题的形式：使用与排错用说明和示例，流程与依赖可用图，复杂主题可用链接的 Wiki 页面或知识地图。沿用用户已有工具与格式，不强制统一为 Markdown。
- 优先修正已有资料。同一事实明确主要维护位置；摘要、图和索引可从它派生或链接回来，避免各自维护不同答案。资料应留在项目或用户指定的现有位置，不只存在于本轮聊天或插件安装目录。
- 图表保留可编辑源或生成数据；知识地图的节点应能定位资料或证据，连线表达有依据的关系。展示图片不能成为唯一难以更新的说明，也不为画图而遍历全仓。
- 区分用户决定、验证事实和暂定判断，重要结论保留足够定位的依据与适用条件。仍影响后续选择的理由不能因精简丢掉；源文件变化只是复核线索，不能机械推断结论错误。
- 不能从代码推断、会影响后续工作的约束，才放进现有项目规则。AGENTS/CLAUDE 不承担任务进度和下一步。
- 同一主题有多个入口时，明确当前版本并修正指针。资料难找时才补短索引；不强建 Wiki、地图、PROJECT、Plan 或 STATE，也不顺带改写全部历史。
- 跨会话工作确有难以恢复的现场时，才保存短 State；简单任务不必为接管补建交接体系。

需要选择图表、Wiki 或说明的形式，或处理主要资料与派生视图时，按需参考 `../../assets/references/project-materials.md` 中的例子；无需每次读取。

复用项目现有名称和路径，保护用户已有内容。移动文件应解决实际查找或权威混乱问题，不为统一目录而迁移；移动前核对引用和目标，完成后修复受影响链接。删除唯一资料、覆盖已有改动和跨仓迁移须符合当前授权，不能由“整理文档”推导出任意清理权限。

## 留下够用的日常规则

仅在项目确有需要时，把以下相关约定简短放入已有入口；不要把整份 Skill 复制过去：

- **是否保存**：会影响以后决策、避免昂贵重复调查或防止错误接续时才写。代码、测试、已有材料或可恢复的 Git 历史已足够，就不另写总结。尚未保存的唯一证据不能假定 Git 已替你保存。
- **工作中维护**：重要决定确认或稳定事实变化后，在当前授权范围内更新已有资料及受影响视图，不必等暂停或收尾。只影响表达、没有新事实的内容不反复改写；不逐轮记日志，也不自动替用户决定换会话或开启新任务。
- **当前方案**：Plan 表达当前有效方案。授权范围内的实现方法、顺序变化直接改写失效段落，已决定的变化不长期作为 State 补丁；范围和验收变化仍需遵循原有授权，不能静默缩水。
- **替代计划**：通常就地修订；路线整体替换、需要独立基线或用户要求保留原稿时，才新建 Plan。旧稿保留正文并标记 `superseded`，新旧互链；新版独立承接剩余范围、约束和验收，当前任务只指向一个有效入口。
- **接续现场**：需要 State 时沿用同一份短快照，只留影响继续执行的现场、阻塞和下一步。完整待办已有 Plan 承载就引用它；仍影响行动的危险中间状态和必要约束不能因压缩丢失。
- **额外材料**：值得记住的独立后续工作进入已有 Issue/Backlog；当前必做项不能移走后算完成。难以重建且有后续价值的证据、非直观且可能复用的经验，才值得独立保存；没有这些收益就不产生 Report 或 Knowledge。
- **按需读取**：链接是查证入口，不是全文必读清单。先读当前问题需要的内容，发现冲突再扩大调查；旧 Plan 和完成历史默认不进入恢复上下文。

这些是选择依据，不要求每个项目都安装一套书面规则。项目已有合适约定时沿用；存在实质冲突才调整。

## 多仓与私有资料

只核对本次涉及的仓库、分支与未提交范围，各仓的权限和提交分别处理。不要把本机绝对路径、密钥或私有数据复制进公开文档。公开仓的必要使用说明不能依赖不可访问的私有材料；私有资料有独立工作入口时，确保从该入口也能定位必要约束。

## 验证并结束

从接手者角度核对：能回答当前目的涉及的目标、结构、理由和状态，知道从哪里继续或查证，不必拼接多份失效材料。图与文字含义一致、关系和链接有依据；生成视觉资料时检查实际呈现，不能仅凭源文件存在就宣称可用。无法查看的形式说明限制，保留真实冲突和未覆盖范围。

向用户说明实际修复、未决冲突与使用入口即可。现有信息已经够用时直接说明，不另写一份“无需写文档”的报告，也不为输出齐全建立迁移清单或长期 State。

可选模板仅在需要对应文件时参考，删掉无用示例与栏目：

- `../../assets/templates/docs-readme.md`：文档多到需要短入口时。
- `../../assets/templates/agents-document-routing.md`：项目确需写下少量信息维护约定时。
- `../../assets/templates/backlog.md`：已有值得暂存的后续事项、又没有合适 Issue/待办入口时。

暂停交接、恢复工作、阶段或任务收尾分别可使用 `checkpoint-project-task`、`resume-project-task`、`closeout-project-task`；无需为了建立入口依次调用它们。
