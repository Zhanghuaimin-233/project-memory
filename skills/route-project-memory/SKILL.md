# 路由项目记忆

把日常执行事件转换为最小、可检索、不会制造第二份真相的项目记忆。不要等待用户知道文档类型，也不要因为发现了信息就必然创建 Markdown。

## 完成标准

- 已读取当前作用域的 AGENTS/CLAUDE 和项目文档入口；
- 已判断事件是否影响当前任务验收；
- 已给出唯一主要落点和必要的关联入口；
- 需要历史证据时只按信号检索相关 Report/Knowledge；
- 没有把证据、未来意图、当前事实和成熟合同混为一类；
- 写入行为没有超出当前任务授权。

## 1. 先确定事件与权限

读取项目现有文档合同、当前任务 State/Plan 和 Git 现场，只加载与本事件直接相关的入口。先确认：

- 这是当前任务必须处理的事项，还是独立未来工作；
- 这是猜测、证据、意图、当前事实、成熟合同还是可复用原因；
- 用户当前授权是实现、文档维护、只读诊断还是仅给建议。

只读或方案请求只输出路由决策，不写文件。实现任务中的正常项目记忆维护可以在同一范围内执行；删除、跨仓移动或其他高风险操作仍需按项目规则处理。

## 2. 选择唯一主要落点

| 事件 | 主要落点 | 边界 |
| --- | --- | --- |
| 不解决就无法满足当前目标或验收 | 当前 State | 继续处理或标为阻塞；不得移入 Backlog 后宣布完成 |
| 与当前验收无关、尚未排期的独立 Bug、优化、技术债或点子 | Issue 或单一 Backlog | 不代表承诺、计划或实现 |
| 已决定近期实施但尚未开始 | Plan | 开始执行后再进入对应 State |
| 已进入实际执行或改变当前任务现实 | State | 记录当前结论和相对 Plan 的偏差 |
| 完整调查、实验、迁移或根因证据，未来重建成本较高 | Report | 保存证据，不自动成为规范 |
| 可能复用但尚未成熟的经验 | State 的“候选经验” | 短任务可留在当前上下文，结束时结算；可能中断时 checkpoint |
| 最小可独立验收范围已完成，可能形成成熟合同或可复用经验 | 转交 `closeout-project-task` | 本 Skill 不自行更新 Spec 或 Knowledge |
| 代码、测试、Git 或当前会话已充分表达 | 不创建长期文档 | “不创建”是一等结果 |

同一事件可以建立链接，但只能有一个主要职责。例如 Report 证明问题存在，Backlog 只记录以后是否处理；不要在两处复制完整正文。

## 3. 维护 Backlog

优先复用项目已有 Issue 系统。没有合适入口且出现真实延期事项时，才创建单一 `docs/BACKLOG.md` 或项目等价文件。

条目保持轻量：

```text
ID
类型：bug / improvement / debt / idea
一句话事项
来源
暂缓原因
完成条件
```

条目被选中实施时进入 Plan，开始执行后进入 State。完成、放弃或被替代后直接从 Backlog 删除，由 Git 保存历史；不维护已完成事项墓地，不为每个条目创建独立 Markdown。

## 4. 创建与检索 Report

Report 按证据价值创建，不按任务长短创建。以下内容仅靠代码、测试或 Git 难以重建时，创建或更新 Report：

- Bug 根因调查；
- 性能、模型或方案对比；
- Provider 或外部工具异常；
- 技术可行性实验；
- 安全审计；
- 数据或文档迁移结果。

普通小修、一次测试结果或显而易见行为不创建 Report。Report 开头尽量记录：

```text
状态
适用模块
相关路径或符号
错误词或主题
结论强度
当前关系：supporting / superseded
```

出现以下信号时，按模块、路径、符号、错误词和主题搜索相关 Knowledge 与 Report：

- 准备修改高风险或历史问题集中模块；
- 遇到非直观异常或相似错误；
- 文档、代码、测试或运行结果冲突；
- State、Knowledge 或 Spec 明确引用历史证据。

不要默认读取全部 `reports/`。若长期结论依赖某份 Report，从 State、Knowledge、Spec 或当前事实入口链接回来。

## 5. 识别并转交结算边界

任务长短不决定是否晋升 Spec 或 Knowledge。判断结论所属的最小可独立验收范围：

- 范围尚未完成：留在 Plan/State/Report，不提前提升；
- 阶段已经独立验收但长期任务继续：使用 `closeout-project-task` 做阶段结算，保留并推进原 State；
- 整个逻辑任务完成：使用 `closeout-project-task` 做任务结算，让任务材料退出 active。

本 Skill 到“建议并转交 closeout”为止，不读取全部完成态材料，不自行创建或更新 Spec/Knowledge，也不归档 Plan/State。

## 6. 输出与验证

统一输出：

```text
事件
决策：写入 / 更新 / 检索 / 不创建
主要类型：State / Issue/Backlog / Plan / Report / closeout / 无文档
目标入口
关联入口
是否影响当前验收
理由
执行结果或待授权事项
```

完成前确认没有制造同主题平行当前文档，没有把当前必做项降级到 Backlog，没有把 Report 当 Spec，也没有绕过 closeout 晋升 Spec/Knowledge 或归档任务材料。
