# 洁癖：同步事实与收尾

让项目资料帮助下一步行动。按实际变化修正入口，不为结算创建文档；零文档改动、没有新经验都是正常结果。本 Skill 自包含，不需要外部 neat 插件。

## 确认范围与依据

先看本次请求、适用规则和 Git 现场。任务已有 STATE 或 Plan 时，读取当前目标、验收边界和未完成事项；再按本次差异查找受影响文档及必要证据。不全量读取历史报告，不把每次收尾变成整个文档库审计。

区分三种情况：

| 当前情况 | 如何处理 |
| --- | --- |
| 一个可独立验收阶段完成，长期任务继续 | 同步本阶段结果，保留并推进原任务 STATE 和有效 Plan |
| 整个逻辑任务的目标与验收均满足 | 同步实际影响，让任务退出活跃入口 |
| 任务或声明完成的范围仍未完成 | 可修正已确认的局部文档；如需交接则更新检查点，明确剩余事项，不作完成结算 |

完成判断依据用户约定、当前实现和适用验证。已有证据仍适用时复用；实现、环境、依赖变化或证据不足时才补相应验证。需要真实运行证据的完成条件不能用静态检查或模拟结果替代。当前验收必做项不能转入 Backlog 后宣布完成；明确约定后置的验收应保留其真实状态。

代码与文档冲突时，查明哪一方偏离已确认约定。实现可能有错，文档也可能过期；不能机械地用代码覆盖需求或合同。无法判定的冲突保留为待决，不写成已确认事实。

## 只修实际受影响的入口

根据改动涉及的功能、路径、命令或合同查找旧说法，优先就地改写。同一事实保留一个权威解释，其他入口只留必要链接。保留有用历史时明确其历史身份，避免与当前方案竞争。

| 内容 | 合适的位置 |
| --- | --- |
| 当前目标、未决事项、继续执行所需现场 | STATE；只留下一步仍需要的部分 |
| 当前有效实施方案和完整剩余验收范围 | Plan；改写失效段落，不把执行偏差长期留在 STATE 当补丁 |
| 已确认的使用、安装、配置或运维变化 | 现有 README 或使用文档，可在任务完成前及时修正 |
| 持续被后续任务、多个模块或外部消费者依赖的合同 | 现有规格入口；独立文档提供代码、Schema、测试之外的语义价值时才新建 Spec |
| Agent 必须知道、且无法从代码直接获得的长期约束 | 适用规则文件；不放任务状态、下一步或完整产品合同 |
| 有复用价值的非直观原因、失败路线或约束 | 现有知识入口；先搜索并合并同主题内容 |
| 难以重建、仍有价值的调查或外部现场证据 | 原证据位置或必要的 Report；长期结论需要时链接回来 |
| 不影响当前验收的独立延期工作 | 现有 Issue 或单一 Backlog；没有真实事项不创建 |

代码、测试、已保存的 Git 历史或已有文档足以表达的内容无需再记。普通修复不必产生 Report、Knowledge 或新规则；未验证猜测不晋升为长期经验。修正规格必须有符合当前授权的决定和证据，草案不能伪装成已生效合同。

知识条目只需使读者知道何时适用、结论是什么、为什么以及依据在哪里。不要复制完整调查过程，不按每次任务新建一篇经验文档。删除陈旧内容前确认没有尚未保存的唯一证据；昂贵或不可重建的现场应保留在合适位置，STATE 仅留仍需要的结论和入口。

## 按完成范围处理任务资料

**阶段完成：** 在同一个 STATE 中保留当前阶段、真实阻塞和下一步，淘汰已解决阻塞、已被 Plan 吸收的偏差、失效下一步和不影响继续执行的完成明细。确有接续作用时保留一条阶段结果及证据入口，不累计阶段流水账。Plan 保留完整剩余范围，正常修订当前方案；只有确需替代时另建新版，并明确旧版 `superseded`、双向链接和唯一当前入口。

**任务完成：** 从活跃索引撤下任务。按项目已有约定归档或标记任务资料，修复受影响链接；没有索引或归档体系时不为形式新建。仍被其他活跃任务使用的 Plan 不归档，独有证据不随任务关闭丢弃。已完成或已放弃的 Backlog 条目退出当前列表；依赖 Git 保存历史前确认内容已被实际保存。

**尚未完成：** 保留活跃任务及未完成验收；已核实的使用文档可以同步，不必等全部完成。若需要结束会话，保存足够继续执行的检查点。临时结论不被提升为稳定合同，当前方案也不能仅存在于历史补丁中。

## 范围与授权

- 默认只处理本任务实际影响的资料。完整仓库或工作区审计仅在明确请求时展开，并仍按线索渐进读取。
- 记忆仅在明确授权后按平台支持的机制维护；不能把项目文档同步视为记忆写入授权，也不直接编辑平台禁止手改的生成记忆。
- 收尾不自动获得删除分支、worktree、用户文件或唯一历史的权限。清场、发布、推送和其他外部动作仅按现场已有授权执行；没有这些请求就不附加此类流程，也不为已授权操作设置额外审批。
- Git 提交与安装同步遵循当前用户和项目规则；本 Skill 不扩大其范围。

## 验证与交付

回读改动，确认现役说法与完成证据一致、链接可用、没有同主题平行当前答案。检查实际 diff，阶段完成时任务仍活跃，任务完成时活跃入口已撤下。只运行与变更和项目要求相关的检查。

简要说明完成范围、实际同步结果和仍待验收或待决的事项；有提交则说明提交状态。无文档改动时直接说明现有入口已准确，无需凑齐固定栏目、事实矩阵或收尾报告文件。
